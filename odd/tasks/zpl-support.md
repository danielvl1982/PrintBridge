# zpl-support

Delivery strategy: ask-on-risk; the forecast is far over 400 authored lines, so the work is delivered as four feature branches merged to `main` one after the other (stacked-to-main), one commit per task, each branch tested and merged on the user's OK. Planning forecast: ~8000 authored lines in 4 groups.

## Objective
Add Zebra ZPL II as the third printer language and give it everything TPCL and TSPL have now: read and draw, write (emit), move, edit
properties (including the content, font, counters and test values), palette insertion, image insertion with rotation, the barcode selector,
and conversion to and from TPCL and TSPL ("Convertir a…"). Reference: `docs/zpl/Zebra_ZPL-II_programming-guide-vol-1_2003.pdf` (local, git-ignored).

## Decisions
- Same exclusions as before: PDF417 / MicroPDF417 (`^B7`, `^BF`), MaxiCode (`^BD`), the text block (`^FB`) and the other out-of-scope symbologies; everything else
  valued for TPCL/TSPL is in.
- The ZPL support follows the existing architecture: a language registered in the registry (detect/parse/emit/...), and one `zpl` factory per component slice
  (`languages: { tpcl, tspl, zpl }`), the shared composeSlices and emit drivers, the neutral model and the data-driven selectors.
- Unverified formats: anything the 2003 guide (Volume One) does not document is marked "not verified on a printer" in code comments and the README.

## Acceptance

- **Serialized fields** (page 41, exercise 5 page 33): the first digit found from the right starts the indexed part, 12 digits at most; `^SNSERIAL NUMBER 00000000111,1,Y` is read and written back as it is (test).
- **Stored formats** (pages 35-37, 42-43): `^FA` (field allocate) is now recognised as having no effect (the manual's own `^CFD^FN1^FA9` example lost its field with an "unsupported command" warning). A recall merges the `^FN` data into the positions of the stored format: now known, still not simulated (the viewer draws the first format of a file).
- **Check digits** (pages 96-97): the Mod 43 example (12345ABCDE/ gives T) and the Mod 10 example (01234567890 gives 5) are pinned as tests.

Not settled by Volume Two (recorded, nothing changed): `^BY` default ratio (only the ratio ranges per symbology), the origin `^FT` and the quiet zone of 2D symbols (the quiet zone page is general: "usually 10 times the narrow bar"), the `^FO` box of rotated bars and the interpretation line, the geometry of the shapes, `^LS` / `^LT`, the settings carried between formats, `^FO`'s third parameter, `^SN` on 2D codes and with `^FN`, `n` = 0, the `^FN` prompt, the ECC 200 range, the QR mixed mode, the Data Matrix encodation, the length of rotated `^FO` text (the advance of the bitmapped fonts is cell + gap: Table 10 says the gap is constant for A..H; font 0 is proportional), and whether `^GF` accepts the compression. The default character set is Code Page 850 (page 60, `^CI` default): UTF-8 bytes above ASCII are not what a printer expects by default.

Open points for the user from this follow-up:
1. **TSPL baseline share**: RESOLVED for the scalable fonts (0.75, the share of the ZPL font 0, so a ZPL <-> TSPL text keeps its top edge); the TSPL bitmap fonts keep 0.8 (no manual gives it) and may differ by a dot or two from the ZPL bitmapped fonts.
2. **Mod 10 of an even-length Interleaved 2 of 5:** the manual counts every other digit from the first position (left anchor), the viewer weighs from the last digit (the EAN way); both agree for an odd number of digits. Which one ZPL uses for an even number is not settled.
3. **Recall of stored formats (`^DF` / `^XF`)** could now be simulated (exercise 6 shows the result) when the format is in the same file: not done.
4. **Z64** would need an inflate decoder (gzip or zlib header: the manual does not say) and the CRC algorithm (not given).
